# Native Ask port demonstration

Before: Seeds had only the library admission trait and synthetic admitted-port tests. There was no executable receipt reader or durable native reservation.

After: the staged executable requires an explicit root-owned immutable profile/code bundle, verifies native evidence through the separately spawned Rikuy program, fsyncs one exclusive reservation and invokes the existing atomic transition. The default command refuses before storage or credentials.

The retained `scoped-writer.txt` is actual output against a disposable native HTTP server and owner-local fixture grant. Ordinary sibling audit is refused without changing the item; project-local full audit succeeds and reads back by item/version. A foreign graph is refused, and a later explicit revocation refuses another transition without changing the version. The fixture never points at production.

The companion Rikuy native qualification joins actual native signing/receipt, HTTPS child process, this Rust port, durable custody and a real in-memory Seeds atomic transaction. See the companion native-seeds-port result for all27 observed controls. That join bypasses only root deployment selection in an ignored test binary; the release command has no override.

These source controls do not establish production installation, grant admission, root artifact custody or human/device acceptance. Project-local audit storage still requires the operator decision. Ordinary CLI audit placement is unchanged.
